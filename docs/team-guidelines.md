# 115-1 軟體工程學期專案｜團隊開發規範（草案）

本文件供三位組員在開發前核對。各模組共用一個儲存庫、一套帳號與同一份資料庫結構。若有規則需要調整，可在本文件的 Pull Request（PR，合併請求）留言，確認後再更新。

## 分工與技術

| 負責人 | 工作範圍 | 功能分支 |
| --- | --- | --- |
| 空間查詢模組組員 | 維護教室資料、公開查詢、樓層位置與全景。另主責共用帳號的註冊、審核、登入及登出。 | `feature/room-list` |
| 空間與物品借用模組組員 | 每週使用狀況、借用申請、審核、物品領用與歸還紀錄。 | `feature/booking` |
| 志願排課模組組員 | 教師志願、管理員排課、衝突檢查、調課申請及通知。 | `feature/scheduling` |

PHP 負責網頁與表單，經由 FastAPI 讀寫資料。FastAPI 統一處理身分驗證、操作權限與業務規則，並連接 PostgreSQL。各模組沿用共用登入。老師可維護自己的課程，管理員可管理全部課程。

## 共用資料與本機設定

- 開發前先確認共用欄位的名稱、型別、主鍵與關聯。三個模組以同一個 `user_id` 辨識帳號，以同一個 `room_id` 辨識教室。教室名稱與用途由空間模組維護。
- 借用和排課採相同的日期與時段定義。建議相鄰時段可銜接，例如 10:00–11:00 與 11:00–12:00。若課程每週重複，需共同約定學期起訖與適用日期。
- 開發時每人使用自己的本機 PostgreSQL，以共用 SQL 建立資料表與起始測試資料。各人的測試紀錄可以不同。整合時在同一台電腦啟動 PHP、FastAPI 與 PostgreSQL，讓三個模組使用同一份資料。
- 誰修改資料庫結構，誰就新增一份依序執行的 SQL 變更檔，和使用該欄位的程式放在同一個 PR。已套用的變更檔保留原樣，後續修正另加新檔。
- 儲存庫共用 `.env.example` 作為設定範本。各人複製成 `.env` 後，在自己的電腦填入實際連線設定與密碼。`.gitignore` 列入 `.env`；使用 GitHub 網頁版上傳時，也要自行確認未選取 `.env`。

## 排課與借用

1. 開學第一週內完成正式排課。排課優先，正式課表已占用的教室時段，不能再核准重疊借用。
2. 課表確定後，老師要調整教室或時段時提出變更申請。處理期間沿用原課表。
3. 調課若碰到已核准的借用，系統通知管理員，列出課程、教室、時段與受影響的借用。管理員協調並確認結果後，再更新課表與借用紀錄。
4. 借用與排課採用同一套占用判斷；正式排課或核准借用時，再依最新紀錄檢查一次。

## GitHub 網頁版協作

1. 每位組員使用自己的 GitHub 帳號。在 Code 頁先選負責的分支，再新增、編輯或上傳檔案。提交說明寫出實際改動。
2. 完成一項可檢查的改動就開 PR。通常以 `main` 為 base（合併目標），工作分支為 compare（改動來源）。共用文件可另從 `main` 建立 `docs/` 開頭的分支。
3. PR 說明寫清楚改了什麼、怎麼驗證。若變更共用欄位、登入或 API，也註明影響哪個模組。請一位組員看過後再合併。
4. 共用變更合併到 `main` 後，使用既有功能分支繼續開發的人，要先把 `main` 的更新合入自己的分支，並在本機套用新的資料庫變更。

## 先功能，後美化

先用基本 HTML 完成表單、按鈕、欄位名稱與操作結果提示。拖曳排課、點選地圖等必要互動跟著功能開發與測試；配色、字型、間距及整體 CSS 待功能完成後統一處理。

## 製作相關功能前再確認

- 哪些教室開放借用、哪些可供排課，由組員討論或向老師確認，再填入共用教室資料。
- 課程採單次或每週重複、實際時段如何表示，由借用與排課組員一起核對後寫入資料規格。
